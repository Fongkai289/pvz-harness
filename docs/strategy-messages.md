## 留在代码中的执行职责

实际可见阳光是否足够、费用是否已知、卡片是否可用/刚使用、格子占用/边界、观察时效、暂停/结束、模型权限与鼠标串行化继续检查。图像校准、点击节流及通信保护属于执行参数，没有把它们改成任意自然语言命令。

Planner 与 Jev 继续独立循环，并不固定1:4。相同规划的原始预算200、已下发预计费用50时，下一次消息给出 initial_allowance=200、committed_spend=50、remaining_advice=150。超过建议时余额可以为负，不能隐瞒超出建议；实际可用阳光单独计算。下发费用仍不等于确认种植成功，保持显式标记。

新观察优先于旧规划文字中的事实陈述。规划上下文把前一条消息标为历史参考，资源变化触发重新规划；无论刷新结果何时到达，都不会用旧建议额度删掉真实可负担的候选。

## RSI 的能力与边界

新日志保存每次 Jev 的完整玩家侧观察、预算及可见植物，规划日志保存实际输入。复盘加入观察与种植决策的关联记录；老日志使用历史记录重建，明确标注时间可能有误差，不借用游戏内存真值补齐玩家输入。

`python -m rsi.replay_strategy --session NAME --decision-id N --coach` 使用既有模型读取完整片段证据并提出 playbook 候选，再用固定观察比较旧消息、新规划、Coach候选。仅写 data/strategy_replays，不修改 CURRENT，不执行鼠标，不把单场景动作变化当作胜率提升或晋升依据。

真实对局自动 LiveReview 诊断后，接入独立 pvz_rl 持久队列，经 state 配对评测和独立截图审计后才能晋升。2026-10-31 本地增加 Coach→Engineer 可变模块代码修改→Windows 开发测试→修复→精确版本提交；Engineer 可自主增删、拆分、合并 player/ 下的模块，输入输出协议、Jev 权限、裁判和晋升标准保持固定。同一份派生观察/模型上下文代码由真实客户端读取，Jev 仍独占种植选择。旧纯消息模式保留为配置选项。具体条件和入口见 [native-rsi.md](native-rsi.md)。当前缺兼容游戏，只有离线与接线验证，没有真实多局成绩；新代码尚因 SSH 网络不通未部署。Emulator 训练不重启。

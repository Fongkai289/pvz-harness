# 自动拾取阳光

2026-10-30：用户批准将权限分为 Planner 规划、Jev 种植决策、代码拾取阳光。

## 触发与权限

- OneJev 模式的 sun_loop 独立运行，每0.25秒检查一轮。Planner 首次规划未返回、零预算、识图模型过期、Jev 等待或失败，都不会阻断拾取。
- 使用原有 HSV/面积检测；候选需出现在两张递增编号的截图中，接收间隔不超过2秒（2026-11-04 由0.8秒放宽：网络慢时约每秒一帧，落地的阳光不动、能留7.5秒，0.8秒会让它整段寿命都确认不了；下落中的阳光每秒移动约67像素，超过40像素的匹配范围，仍等落地后再拾），位置曼哈顿距离不超过40像素，面积比0.5–2。仅在当前800×600坐标系中 x∈[0,780)、y∈[90,570) 拾取。
- 只允许0.8秒内的当前截图；排除整个卡片/铲子/菜单区及底部进度条。客户端的游戏就绪、焦点、暂停和结束检查继续生效。
- 同位置去重沿用当前 playbook.fast（当前2秒/30像素）。每批最多2次点击，持有种植使用的同一操作锁，不能插入选卡与落点之间。
- 发送前重新检查当前截图、对局状态和本次目标授权。单独伪造 decision_source 标签不能授权任意点击。
- Jev 候选仅含种植或等待；Planner 和 Jev 提示词明确自动拾取职责。没有新增模型角色，也不借助真实内存检测阳光。
- 显式 rules 对照基线保留原有采集方式，避免改变已有离线基准。

## 观察与限制

日志 sun_collection 记录检测数、连续帧确认数、已下发点击及累计；cmd.meta.decision_source 标明 sun_collector 或 onejev。控制台显示自动拾取状态，并把代码点击与 Jev 点击区分开。点击数是已下发数，不宣称实际成功拾取数量。

连续帧确认能过滤单帧噪点，不能证明所有黄色物体都是真阳光。已有真实截图 00000473 的三个候选对应三处可见阳光；仍需后续对局检查遮挡、误识别和漏检。这里没有实时修改阳光余额，也不预测拾取后的收入；预算始终依据后续画面识别。
